想写博客的人，第一个念头往往是「去买一台服务器」。这个念头是错的，而且代价不小。

## 博客是静态的

服务器存在的意义，是**在每次请求时现场算出一个结果**。评论区要查数据库，登录要校验密码，搜索要跑查询——这些才是动态的，才需要一台一直开着的机器。

而博客不是。一篇文章写完之后，它的 HTML 永远是同一份字节。你唯一需要的是**把这些字节放在离读者近的地方**，然后让 CDN 帮你分发。

用一台服务器去托管一个静态页面，等于为了送一封信专门雇了一个司机，还让他 24 小时待命。

## 具体贵在哪里

| 项目 | 自建服务器 | 静态托管 |
| --- | --- | --- |
| 机器 | 100~1000 元/年 | 0 |
| 证书续期 | 自己配、自己盯 | 自动 |
| 备份 | 自己写脚本 | 内容在 Git 里 |
| 被扫描、被爆破 | 自己处理 | 无服务器可攻 |
| 流量突增 | 可能被打爆或欠费 | CDN 兜住 |

注意第二行和第四行。**真正贵的不是钱，是注意力。**一台暴露在公网的服务器，会持续向你要东西：证书过期了、系统有漏洞了、磁盘满了、日志里有人在扫你的 SSH。

这些事情单次花费不多，但它们会不断打断你。而写博客最需要的东西，恰恰是不被打断。

## 那什么情况下确实需要

有三种：

1. 你要做**服务端渲染**的站，页面内容依赖登录状态或实时数据
2. 你要跑**定时任务**，比如每天抓一次数据、发一封邮件
3. 你要存**用户上传的文件**，且不想用对象存储

除此之外，静态托管都够用，而且更快。

## 一个反直觉的点

静态站看起来「简陋」，实际上在速度上吊打绝大多数动态站。原因很直接：

```bash
# 动态站的一次请求
请求 → 路由 → ORM 查询 → 模板渲染 → 返回
      （每一步都可能慢，都可能出错）

# 静态站的一次请求
请求 → CDN 命中 → 返回
      （没有第二步）
```

首字节时间差一个数量级是常态。读者感知到的不是一个技术指标，而是「点开就有」和「转了一下圈」的区别。

## 结论

先写，别先搭。内容攒到十篇之前，用什么托管都不重要；攒到十篇之后，你会自己知道缺什么。

> 工具应该消失在工作里。如果你每天都在想你的博客系统，那说明选错了。
